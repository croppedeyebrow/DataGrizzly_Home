# 24. 출시 검증과 운영 인계

완료는 코드 존재가 아니라 실제 동작과 복구 증거

## 사용자 기능

관리자가 프로젝트 설명·과정 기록·학습·논문·뉴스를 작성하고 첨부·미리보기·발행할 수 있습니다. 공개 웹에서 정상 이동하고 모바일에서도 본문·코드·수식이 읽혀야 합니다.

## 불변조건 검증

초안 수정으로 공개본이 바뀌지 않음, 미인증 초안 접근 차단, 중복 발행 단일 처리, 오래된 작업의 덮어쓰기 방지, 철회한 글의 검색·답변 재노출 방지, 첨부 참조 보존을 통합 시나리오로 확인합니다.

## 부하·장애 검증

측정 환경과 입력을 기록하고 검색 p95 목표 1초 이내를 초기 기준으로 둡니다. 생성 목표는 후보 장비 측정 후 정합니다. API·DB·모델·작업자 종료와 디스크 부족을 각각 재현하여 공개 읽기와 저장 데이터 영향을 확인합니다.

## 운영 문서

로컬 실행, 환경값, 배포 절차, 현재 digest, DB 마이그레이션, 발행 실패 재시도, 검색 인덱스 재생성, 철회, 모델 비활성화, 백업 복원, 비밀값 교체 절차를 docs/runbooks에 기록합니다.

## 인계 산출물

소스·OpenAPI·JSON Schema·ERD·다이어그램·마이그레이션·Compose·workflow·dgops·평가셋·복구 증거·릴리스 manifest를 포함합니다. 완료된 작업만 프로젝트 과정 기록으로 공개하고 측정하지 않은 성능 수치를 쓰지 않습니다.
