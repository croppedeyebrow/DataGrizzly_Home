# AI와 개발하는 작업 절차

## 처음 시작할 때

1. 이 폴더를 저장소의 `docs/datagrizzly`에 복사합니다. 프로젝트 루트에 놓아도 됩니다.
2. 최초에는 README → ZERO_START → S00, 기능 개발에서는 CONTRACTS → 해당 아키텍처 → 기능 명세 → 단일 태스크 순서로 읽습니다.
3. 완전 초기 환경의 최초 작업은 S00입니다. S19 완료 후 M0-01로 이동합니다. 저장소가 이미 있으면 구현 현황을 검사하여 재사용 범위를 먼저 기록합니다.
4. 작업 보드에서 선행 태스크 완료 증거를 확인합니다. 한 번에 전체 32개를 구현하도록 요청하지 않습니다.

## AI 작업 원칙

- 문서 상태는 모두 구현 전입니다. 코드 존재와 실제 동작을 구분합니다.
- v2.0 제품 범위를 유지합니다. 이 세트의 상세 필드·경로는 구현 제안이며 M0 계약에서 확정합니다.
- 요구 충돌 시 임의 선택하지 말고 충돌 위치와 영향을 기록합니다. 확정된 새 ADR이 이전 제안을 대체합니다.
- 현재 저장소의 AGENTS.md와 빌드 명령을 읽습니다. 이 문서는 실행 환경의 권한을 부여하지 않습니다.
- 외부 배포·유료 자원·비밀값 변경은 현재 작업의 사용자 승인 범위를 따릅니다.
- 기술 버전과 패키지 API는 착수 때 공식 문서로 확인하고 lockfile/toolchain에 고정합니다. 이 문서는 최신 버전을 보장하지 않습니다.
- 작고 검토 가능한 변경을 만들고 관련 위험을 검증합니다. 무관한 리팩터링과 과도한 마이크로서비스 분리는 하지 않습니다.
- 테스트를 실행할 수 없으면 이유와 사용자가 실행할 명령을 남깁니다. 성공 로그를 만들어내지 않습니다.

## 작업 종료·다음 대화 인계

각 태스크 하단의 완료 기록을 채우고 TASK_BOARD 상태를 갱신합니다. 세션이 바뀌면 HANDOFF_TEMPLATE을 채워 다음 AI에게 제공합니다. 검증되지 않은 기능은 완료로 옮기지 않습니다.

## 문서 정밀도와 미결정 항목

OpenAPI, JSON Schema, SQL migration, Compose 파일은 아직 실제 코드가 아닙니다. M0-02와 M2-01에서 생성·검증해야 합니다. 에디터·인증 제공자·호스팅·예산은 DECISIONS에서 결정하며, C++ 모델 선정은 M7까지 미룹니다.
