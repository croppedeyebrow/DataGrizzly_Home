프로젝트 설명/과정 기록 분리, 발행된 공개 페이지의 정적 출력, PostgreSQL 검색 유지·생성 제외, 필요 시 Go 배포 CLI, Python 워크플로를 M8에서 추가합니다. 공개 웹과 관리자는 React·TypeScript·Tailwind, 업무 API는 Rust(Axum)다.

현재 환경: Windows 우선, 도구는 단계별 설치. Rust 단계에서 WSL 환경을 준비하고 Python은 S20부터 준비합니다. C++은 제외합니다. [[03_EXECUTION_PLAN]]

## ADR-09 프론트와 API 스택

- 문제: 공개 웹, 관리자, 업무 API가 서로 다른 구현 기술을 따르면 화면과 서버가 한 체계로 이어지지 않는다.
- 후보: 기술을 나누어 유지, 프론트만 React로 통일, API만 Rust로 두기, 프론트와 API를 함께 맞추기.
- 선택: 공개 웹과 관리자를 React·TypeScript·Tailwind로 만들고, 업무 API를 Axum으로 만든다.
- 근거: 화면 기술을 하나로 두고, 인증·저장·발행·검증을 Rust 프로세스에 모은다. 경로, 초안 비공개, PostgreSQL 원본은 유지한다.
- 비용·위험: 공개 페이지와 health는 2026-11-01에 이전했다. 데이터베이스 접속은 아직 없다. 공개 글은 발행 빌드의 정적 HTML로 남겨 API 중단 시에도 읽히게 한다.
- 재검토 조건: Rust 서버가 로컬 health와 15432 접속을 통과하지 못하면 이 결정을 다시 연다.
- 영향 태스크: S13-1. 다음 구현은 S14, Axum의 데이터베이스 접속과 메타 마이그레이션이다.
- 날짜: 2026-11-01
