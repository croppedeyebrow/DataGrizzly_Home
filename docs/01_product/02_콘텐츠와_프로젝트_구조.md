# 02. 콘텐츠와 프로젝트 구조

> v5.0 기준: [[SCOPE_v5]] 적용. 주력 Kotlin·Rust·TypeScript·PostgreSQL. LLM·C++ 제외, Go는 국소 배포 도구로 필요할 때만 사용합니다. 로컬 자원은 [[02_RESOURCE_BUDGET]] 참조.
프로젝트 설명은 전체 지도, 과정 기록은 판단의 이력

## 프로젝트 설명

해결하려는 문제·사용자·목표·범위·구조·기능·기술 선택·담당 범위·결과·한계·GitHub·데모를 기록합니다. 기획/개발/공개/유지보수 상태와 최종 갱신일을 표시합니다.

## 과정 기록

한 기록에 하나의 질문이나 변경을 담습니다. 배경 → 재현/요구 → 대안 → 선택 이유 → 구현 → 검증 → 한계 순서입니다. project_id, 단계, 순서, 관련 커밋·이슈·노트를 연결합니다. 생성일과 프로젝트상의 읽는 순서는 별개입니다.

## 독립 학습과 리서치

언어·CS·AI·ML·비전·수학·물리·화학·제어·인프라·보안 노트를 유지합니다. 논문 리뷰와 도메인 뉴스는 출처·사실·해석·재현 여부를 구분합니다. 기초 학습에 프로젝트 연결을 강제하지 않습니다.

## 분류와 관계

콘텐츠 종류, 주제, 태그, 시리즈, 프로젝트 관계를 독립적으로 관리합니다. 과정 기록의 원문 URL은 하나만 두고 다른 목록은 링크합니다. 한 프로젝트에 여러 과정 기록을 연결하고 필요 시 보조 프로젝트 관계를 허용합니다.

## 시안 변경

홈의 실험실 영역을 최근 프로젝트 과정 기록으로 교체합니다. 기존 실험 목록/실행/결과 템플릿은 출시 페이지에서 제거합니다. 노트·리서치 상세 스타일은 유지하고 프로젝트 상세에 설명/과정 기록 탭을 추가합니다.
