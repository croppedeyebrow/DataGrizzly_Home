# 14. RAG 품질·보안·비용

답변보다 원문과 공개 상태가 우선

## 검색 단계

제목·소제목·코드 경계를 보존해 분할합니다. 길이만으로 자르지 않고 원문 anchor를 유지합니다. 검색 상위 후보를 중복 제거해 제한된 근거만 사용합니다. 임베딩 검색과 벡터 DB는 평가에서 필요성이 확인된 후 추가합니다.

## 생성 제약

질문과 근거를 구분하고 문서 내 지시문은 실행 명령으로 취급하지 않습니다. 모델에는 도구 실행·관리 API 권한을 주지 않습니다. 근거가 부족하면 답변하지 않습니다. 출처 ID 존재 검사는 의미적 정확성 검증을 대신하지 않으므로 별도 평가합니다.

## 공개 상태와 캐시

인덱스 전환 전에도 Kotlin이 현재 공개·철회 ID를 검사합니다. 생성 전후 공개 상태를 재확인합니다. 캐시 키에는 정규화 질문·scope·releaseId·modelVersion·promptVersion을 포함하고 철회 시 관련 캐시를 무효화합니다.

## 자원 제한 초기안

생성 동시 실행 1개, 짧고 제한된 대기열, 최대 출력 토큰·입력 길이·요청 시간 제한을 둡니다. 정확한 제한값은 벤치마크로 확정합니다. idle unload는 메모리를 줄일 수 있으나 VM 기본요금을 없애지 않으며 재로딩 지연이 생깁니다.

## 공개 게이트

한국어 질문 30개: 검색 가능 20개·근거 없음 5개·초안/철회 5개로 시작합니다. 검색 가능한 질문 Recall@5 목표 80% 이상, 출처 링크 유효성 100%, 비공개 노출 0건을 점검합니다. 생성 답변은 수동 근거 평가 90% 이상을 목표로 두되 작은 평가셋의 결과를 일반 성능으로 주장하지 않습니다.
