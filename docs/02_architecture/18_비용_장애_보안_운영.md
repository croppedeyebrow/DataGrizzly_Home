# 18. 비용·장애·보안 운영

> v5.0 기준: [[SCOPE_v5]] 적용. 주력 Kotlin·Rust·TypeScript·PostgreSQL. LLM·C++ 제외, Go는 국소 배포 도구로 필요할 때만 사용합니다. 로컬 자원은 [[02_RESOURCE_BUDGET]] 참조.
비용은 목표 예산과 측정값으로 결정

## 비용 산정식

월 비용 = 서버 실행 + 객체 저장 + 전송 + CI 실행/보관 + 백업 + 도메인. 단가와 무료 한도는 업체 선택 후 확인합니다. 사용량 시나리오: 월 1천/1만/10만 페이지 조회, 생성 요청 0/하루 20/하루 100건을 비교하고 용량·요청당 CPU 시간을 실측합니다.

## 비용 제어

모델 없는 검색을 기본 공개합니다. 생성형 추론 비용은 현재 구성에 없습니다. 배포·인덱싱은 필요한 시점에 실행하고 동일 스냅샷 중복 빌드는 합칩니다. 예산 알림은 자동 지출 차단과 다르므로 요청 상한도 둡니다.

## 장애 대응

API/DB 장애: 정적 읽기 유지, 작성·검색 상태 안내. DB 검색 장애: 제목·태그 기반 경량 검색 fallback 또는 검색 일시 중단 표시. 빌드 실패: 기존 공개 세대 유지. 단일 서버의 공통 장애 위험은 수용하고 확장은 측정 후 결정합니다.

## 세대 전환과 복귀

CDN·DB·인덱스는 단일 트랜잭션이 아니므로 pending/active 세대를 기록하고 전환 결과를 재조정하는 작업을 둡니다. 검색 인덱스가 늦으면 이전 세대 결과를 최신 공개 정책으로 필터링합니다. 철회 denylist는 롤백으로 해제하지 않습니다.

## 운영 지표

API 오류·저장 실패·발행 대기/실패·인덱스 지연·검색 무결과·생성 지연·RSS 메모리·디스크·백업 최근 성공을 관측합니다. requestId/jobId/releaseId를 연결하고 로그 보존·용량 제한을 둡니다. 기본 Compose 교체는 무중단이나 고가용성을 보장하지 않습니다.

## v5.0 자료 워크플로 반영

추론 비용 대신 자료 파싱·artifact·checkpoint 보존 비용을 관리합니다. worker-off는 CMS 장애가 아니며 URL fetch 보안은 [[WF05_SECURITY_LIMITS]]를 적용합니다.
