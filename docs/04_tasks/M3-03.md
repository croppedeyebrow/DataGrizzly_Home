> v5.0 실행 기준: **PUBLISH**. [[SCOPE_v5]]와[[02_RESOURCE_BUDGET]]를 적용합니다. 실제사양7530U/13.8GiB/C:23.4GiB. 설치시점은[[03_EXECUTION_PLAN]]을 따릅니다.
- 상태: 구현. 철회는 공개 포인터를 바로 비우고, 더 나중에 확인된 세대가 있으면 예전 작업의 성공 기록을 거절한다. 외부 캐시 삭제와 격리 DB 통합 시험은 미실행. 예약 발행은 M3-04다.

- 원기획 선행 작업: M3-02
- 실행 시 추가 확인: 없음
- 적용 버전: 문서 v3.0 / 제품 범위 v2.0
- 예상 변경 경로: `services/api/publication, services/api/discovery` (제안 경로; 실제 저장소 확인 후 대응 경로 기록)

## 생성·수정할 산출물

`services/api/publication/releases/**; discovery/denylist/**`

파일명이 아직 없으면 해당 책임에 맞는 파일을 만듭니다. 경로를 변경하면 관련 명령과 연결 문서도 함께 고칩니다. 여러 파일을 한 파일로 억지로 합치지 않습니다.

## 세부 구현 작업

### M3-03.01 — 세대 단조 증가

- **할 일:** 사이트별 활성화 직렬화와 release sequence 비교를 구현합니다. 오래된 작업의 성공 통지는 무시/거부합니다.
- **단계 완료 결과:** 최신본을 예전 작업이 덮지 못함
- **기록:** 변경 파일과 이 조건을 확인한 명령/관측값을 작업 기록에 남깁니다.

### M3-03.02 — 철회 먼저 차단

- **할 일:** Entry denylist를 영속 저장하고 검색/질문/공개 API에서 즉시 적용합니다.
- **단계 완료 결과:** 검색 인덱스 재빌드 전에도 차단
- **기록:** 변경 파일과 이 조건을 확인한 명령/관측값을 작업 기록에 남깁니다.

### M3-03.03 — 정적·첨부 회수

- **할 일:** 현재와 이전 release의 해당 HTML·첨부 접근 정책을 점검하고 CDN purge/삭제를 추적합니다. origin release URL을 통한 우회 접근도 정책에 포함합니다.
- **단계 완료 결과:** 외부 캐시 한계와 실제 완료 범위를 표시
- **기록:** 변경 파일과 이 조건을 확인한 명령/관측값을 작업 기록에 남깁니다.

### M3-03.04 — 복귀 필터

- **할 일:** 과거 release로 복귀할 때 이후 철회 목록을 그대로 적용합니다. static 호스팅이 이를 즉시 적용 못하면 안전한 재빌드 또는 접근 차단이 끝날 때까지 복귀를 보류합니다.
- **단계 완료 결과:** 과거 release 재활성화로 철회 글 재노출 금지
- **기록:** 변경 파일과 이 조건을 확인한 명령/관측값을 작업 기록에 남깁니다.

### M3-03.05 — 운영 재시도

- **할 일:** purge 일부 실패를 별도 상태로 유지하고 retry합니다. 작업 성공과 외부 캐시 회수 보장을 구분합니다.
- **단계 완료 결과:** 철회 작업의 미완료 항목이 보임
- **기록:** 변경 파일과 이 조건을 확인한 명령/관측값을 작업 기록에 남깁니다.

## 입력·오류·경계 검증

역순 배포완료, CDN purge 실패, 이전release origin 접근, 철회후 rollback, 첨부 직접URL을 확인합니다.

정상 케이스만 확인하지 않습니다. 입력이 잘못된 경우, 선행 자원이 없는 경우, 관련 외부 컴포넌트가 실패한 경우를 구분합니다. 실제 실패 주입이 불가능하면 미실행으로 적고 실행 환경을 명시합니다.

## 실행 방법과 증거

[명령 계약](../00_guide/COMMANDS.md)의 해당 구성요소 검사부터 실행합니다. 기능 테스트가 아직 없으면 이 태스크의 위험을 검증하는 테스트를 작성한 뒤 실제 명령을 기록합니다. 빌드 성공은 기능 수용조건 충족과 별개입니다.

| 검증 구분 | 확인 대상 | 남길 증거 |
|---|---|---|
| 계약 | 연결 기능 명세·schema·API 응답 | 입력/응답 예제, schema 검증 결과 |
| 정상 동작 | 위 세부 작업의 완료 결과 | 테스트 이름·실행 명령·결과 |
| 실패 동작 | 위 경계·오류 시나리오 | 재현 절차·오류코드·상태 보존 결과 |
| 회귀 | 영향을 받은 기존 공개/관리 흐름 | 관련 테스트 결과·변경 전후 차이 |

## 실패 시 복구·중단 기준

- 파일/명령 없음: 아직 산출물을 생성하지 않았는지 먼저 확인합니다. 가짜 성공 스크립트로 통과시키지 않습니다.
- 계약과 코드 불일치: producer/consumer/fixture를 함께 검토하고 schemaVersion 변경 필요성을 기록합니다.
- 데이터 변경 실패: 트랜잭션·migration 이력을 확인합니다. 개발 DB 전체 삭제를 기본 해결법으로 쓰지 않습니다.
- 선행 태스크 결함: 해당 ID와 재현 증거를 남기고 현재 작업 완료를 보류합니다.
- 리소스 부족: 측정값을 남기고 선택 기능을 비활성화합니다. 승인되지 않은 유료 자원을 자동 생성하지 않습니다.

## 작업 완료 기록

세부 작업 ID별로 완료/미완료와 증거를 적습니다. 다음 대화에 현재 세부 작업 ID를 전달합니다.


- 작업 브랜치/커밋: `feat/m3-publish`. 커밋은 하지 않았다.
- 변경 파일: `services/api/migrations/0008_withdrawal.sql`, `services/api/src/withdrawal.rs`, `services/api/src/snapshot.rs`, `services/api/src/main.rs`, `services/api/src/catalog.rs`, `services/api/src/admin.rs`, `services/api/src/publication.rs`, `services/api/src/revisions.rs`, `apps/admin/src/publications/Publications.tsx`, `apps/admin/src/editor/Editor.tsx`, `docs/03_features/F10_철회_예약_세대관리.md`, `docs/contracts/routes.md`, `docs/09_screen_specs/A10.md`
- 검증 명령과 결과: `services/api`에서 `CARGO_BUILD_JOBS=2`, `cargo test -j 2`는 25개 통과, 6개 무시. 더 나중에 확인된 세대가 있으면 활성화 결정은 stale이고, 철회된 글은 withheld다. 공개 여부는 공개 포인터가 있고 철회 목록에 없을 때만 참이다. 철회된 글의 과거 릴리스 복구는 refuse다. 철회 메모는 외부 캐시 삭제를 보장하지 않는다고 적고, 회수 실패는 공개 API 차단이 유지된다고 적는다. 관리자 `tsc -b`는 종료 코드 0이다. 로그인 전 5173에서 `/admin/publications`를 열었다. 제목은 발행 작업이고 `로그인이 필요하다.`가 보이며, 철회 완료로 보이는 예시 행은 없다. 1440px와 390px에서 문서 너비는 각각 1440, 390이다. 확인 후 5173은 종료했다. 격리 DB의 철회 접수, 첨부 404, 세대 역전은 `datagrizzly_m2`가 필요해 미실행이다. 127.0.0.1:15432는 닫혀 있다. 외부 CDN purge는 호출하지 않았다.
- 근거 파일/로그: `services/api/src/withdrawal.rs`의 `activation_decision`, `rollback_decision`, `public_visible`, `withdrawal_memo`
- 남은 문제: 로그인 뒤 철회 버튼, 철회 목록, 첨부 직접 주소 404, 오래된 작업의 DB 거절은 아직 실행 전이다. 로컬 릴리스 폴더의 `withdrawn` 표시는 외부 캐시 삭제와 별개다. 검색 화면과 예약 발행은 만들지 않았다.
