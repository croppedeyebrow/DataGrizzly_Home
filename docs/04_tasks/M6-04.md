- **단계 완료 결과:** 예산 알림과 hard cap 구분
- **기록:** 변경 파일과 이 조건을 확인한 명령/관측값을 작업 기록에 남깁니다.

- **기록:** 변경 파일과 이 조건을 확인한 명령/관측값을 작업 기록에 남깁니다.

### M6-04.04 — 장애 안내

- **할 일:** API/DB/C++ 중단 때 공개 읽기와 관리자 오류를 확인합니다. 단일 서버 공통장애 한계를 runbook에 명시합니다.

## 입력·오류·경계 검증

익명 관리 API 차단, robots/sitemap/초안 접근, 기능 전체 여정, 원격 백업 복원 증거를 점검합니다.

정상 케이스만 확인하지 않습니다. 입력이 잘못된 경우, 선행 자원이 없는 경우, 관련 외부 컴포넌트가 실패한 경우를 구분합니다. 실제 실패 주입이 불가능하면 미실행으로 적고 실행 환경을 명시합니다.

## 실행 방법과 증거

[명령 계약](../00_guide/COMMANDS.md)의 해당 구성요소 검사부터 실행합니다. 기능 테스트가 아직 없으면 이 태스크의 위험을 검증하는 테스트를 작성한 뒤 실제 명령을 기록합니다. 빌드 성공은 기능 수용조건 충족과 별개입니다.

| 검증 구분 | 확인 대상 | 남길 증거 |
|---|---|---|
| 계약 | 연결 기능 명세·schema·API 응답 | 입력/응답 예제, schema 검증 결과 |
| 정상 동작 | 위 세부 작업의 완료 결과 | 테스트 이름·실행 명령·결과 |
| 실패 동작 | 위 경계·오류 시나리오 | 재현 절차·오류코드·상태 보존 결과 |
| 회귀 | 영향을 받은 기존 공개/관리 흐름 | 관련 테스트 결과·변경 전후 차이 |

## 실패 시 복구·중단 기준

- 파일/명령 없음: 아직 산출물을 생성하지 않았는지 먼저 확인합니다. 가짜 성공 스크립트로 통과시키지 않습니다.
- 계약과 코드 불일치: producer/consumer/fixture를 함께 검토하고 schemaVersion 변경 필요성을 기록합니다.
- 데이터 변경 실패: 트랜잭션·migration 이력을 확인합니다. 개발 DB 전체 삭제를 기본 해결법으로 쓰지 않습니다.
- 선행 태스크 결함: 해당 ID와 재현 증거를 남기고 현재 작업 완료를 보류합니다.
- 리소스 부족: 측정값을 남기고 선택 기능을 비활성화합니다. 승인되지 않은 유료 자원을 자동 생성하지 않습니다.
