## 결정

공개 화면과 관리 화면은 React, TypeScript, Tailwind CSS로 만든다. 업무 API는 Tokio 위의 Axum으로 만든다.

화면 목록, 경로, 초안과 공개의 구분, PostgreSQL 원본, 소유자 한 명의 인증, 생성형 답변 제외는 유지한다. S13의 데이터베이스 `127.0.0.1:15432`와 named volume `datagrizzly_pg`도 유지한다.

## 목표 구조

| 영역 | 목표 | 현재 코드 |
|---|---|---|
| 공개 웹 | Vite, React, TypeScript, Tailwind. 경로는 지금과 같다 | `apps/web` Vite·React 19.3.1·TypeScript 6.0.3·Tailwind 4.3.3. 정적 HTML |
| 관리자 | 같은 프론트 스택. 빌드 산출물은 공개 웹과 분리 | `apps/admin` Vite, React 19.3.1, TypeScript. Tailwind는 아직 없음 |
| 공유 UI | Tailwind 테마와 블록 렌더러. 기존 design token을 테마 값으로 옮긴다 | `packages/design-tokens`. 공개 웹 테마에 연결됨 |
| 업무 API | Rust 프로세스 하나. 인증, 글, 발행, 검색 API | `services/api` Axum 0.8 health. 데이터베이스 접속은 아직 없음 |
| 저장 | PostgreSQL 16.10 컨테이너 | S13에서 기동됨 |

공개 웹과 관리자는 기술을 같이 쓰고 배포 단위는 나눈다. 관리자 묶음이 공개 페이지에 실리지 않게 한다.

## 프론트

`apps/web`과 `apps/admin` 모두 Vite와 React 19, TypeScript, Tailwind를 쓴다. 관리자에 이미 있는 Vite, React 19.3.1, TypeScript 6.0.3을 재사용하고 Tailwind만 더한다. Tailwind 버전은 구현을 시작할 때 공식 안정판을 확인해 고정한다.

공개 경로는 `docs/contracts/routes.md`의 P01~P15를 유지한다. 공통 틀은 React 레이아웃이 맡는다. 헤더, 메뉴, 본문, 푸터는 `apps/web/src/site/layout.tsx`에 있다. 글 블록은 같은 스키마를 React 컴포넌트로 그린다. 색과 글꼴은 기존 토큰을 Tailwind 테마에 넣어 두 앱이 한 벌을 쓰게 한다.

공개 글은 발행 빌드가 정적 HTML로 뽑는다. 방문자는 그 파일로 읽고, API가 멈춰도 이미 발행된 글은 열린다. 검색처럼 요청이 필요한 화면만 브라우저에서 Rust API를 호출한다. 관리자는 브라우저 앱으로 두고 저장, 발행, 로그인에만 API를 쓴다.

## 백엔드

로컬 API는 이 PC에 이미 있는 Windows Rust 1.92.0으로 만든다. Ubuntu 설치를 기다리지 않는다. 서버는 Tokio 위에서 Axum으로 HTTP를 받고, PostgreSQL은 SQLx로 접속한다. 크레이트 버전은 구현 착수 때 Rust 1.92와 맞는 안정판으로 고정한다.

프로세스 환경으로 접속 정보를 넣는다. 비밀번호는 `.env`에만 두고 저장소와 로그에 남기지 않는다. 프레임워크가 `.env`를 자동으로 읽는다고 가정하지 않는다. 연결 풀은 최대 4, idle 1에서 시작한다. 첫 마이그레이션은 접속 확인용 메타만 만든다. 업무 테이블은 M2-01까지 만들지 않는다.

모듈 경계는 Rust 워크스페이스에 둔다. 인증, 글과 수정본, 프로젝트, 분류, 미디어, 발행, 검색, 감사 기록이다. 콘텐츠 검증과 정규화도 이 워크스페이스의 라이브러리가 맡는다. Python 워커가 나중에 붙으면 API로 초안을 넣고, 테이블에 직접 쓰지 않는다.

health는 `services/api`의 Axum이 맡는다. 데이터베이스 접속은 아직 없다.

## 착수하지 않을 작업

S14는 Axum이 `127.0.0.1:15432`에 접속하고 메타 마이그레이션만 적용하는 작업이다. S16의 Ubuntu Rust 설치는 로컬 API의 선행 조건이 아니다. M2의 저장과 편집은 React 관리자와 Rust API가 맡는다.

## 구현 순서

공개 페이지와 health는 이전했다. 아래는 남은 구현의 순서다.

1. 관리자와 공개 웹에 같은 Tailwind 테마를 둔다.
2. 공개 경로를 React 페이지로 바꾸고, 발행 빌드가 정적 HTML을 만드는지 확인한다.
3. Rust 서버가 로컬에서 기동되고 health를 반환하는지 확인한다.
4. Rust가 S13 데이터베이스에 접속하고 메타 마이그레이션만 적용하는지 확인한다.
5. 그 다음에 인증과 글 저장을 구현한다.

한 번에 공개 웹 개발 서버, Rust 빌드, 데이터베이스를 같이 켜지 않는다. 이 PC는 메모리 13.8GiB다.
