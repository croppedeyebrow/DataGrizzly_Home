# S21 체크포인트·권한·환경값 준비

상태: 미착수. 선행: [[S20]], PostgreSQL 개발 인스턴스. [[WF04_DATA_API]]

1. 워커 전용 DB 사용자와 checkpoint schema 또는 별도 DB를 설계합니다. CMS 테이블 쓰기 권한이 없어야 합니다.
2. workers/document-workflow에서 `uv add langgraph-checkpoint-postgres "psycopg[binary,pool]"`를 수행하고 버전 호환·lock diff를 확인합니다.
3. .env.example에는 CMS_INTERNAL_BASE_URL, WORKFLOW_CHECKPOINT_DSN, WORKFLOW_TOKEN, WORKFLOW_VERSION, WORKFLOW_MAX_JOBS=1을 이름/예시로만 작성합니다. 실제 secret은 .env 또는 환경으로 주입하며 자동 .env 로딩을 구현했는지 확인합니다.
4. 버전별 공식 API에 맞춰 checkpointer setup 전용 명령을 만듭니다. 관리 migration 계정과 런타임 계정을 구분하고 setup은 임의 매 실행마다 수행하지 않습니다.
5. 단순 state의 값을 저장하는 graph를 한 번 실행하고 프로세스를 완전히 종료합니다. 같은 thread_id로 새 프로세스에서 읽어 persistence를 확인합니다.
6. 다른 schema의 CMS 테이블 수정 시도가 권한 오류인지 확인합니다. 로그에서 DSN 암호·토큰을 마스킹합니다.

완료 조건: 재시작 복구 증거, 최소 권한 검사, schema/DB 격리 기록, setup 재실행의 안전성, backup 대상 등록. 실패 시 DB 전체 삭제 대신 신규 schema만 검토하며 기존 CMS 데이터를 보존합니다.
