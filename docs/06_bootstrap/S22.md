# S22 워커 실행 골격·Rust 연결·기본 CI

상태: `feat/s22-worker-shell`에 실행 골격과 Rust 계약 확인을 넣었다. 문서 워크플로 구현은 아니다. 선행: [[S21]], M4 Rust CLI.

1. cli.py에 --once/--drain/--job 인자와 명확한 종료 코드를 정의합니다. 작업 없음은 정상 종료입니다.
2. 환경 누락은 실행 시작 전에 실패시키고 secret을 출력하지 않습니다. 로컬 Rust 내부 API 주소를 공개 URL과 구분합니다.
3. Rust CLI 계약 버전 확인 명령을 만들고 OS별 실행 어댑터를 분리합니다. Windows에서는 WSL Rust 바이너리에 JSON stdin을 넘기는 smoke 테스트를 수행합니다. WSL 경로를 Windows 파일 경로로 추정하지 않습니다.
4. 작은 합성 문서 하나를 입력해 stdout JSON schema와 종료 코드를 검사합니다. timeout/오류시 임시 파일만 정리합니다.
5. ruff·mypy·pytest 설정을 만들고 Python 경로 변경 시에만 실행하는 CI job을 추가합니다. CI는 lock 기반 설치, 외부 live fetch 없음, 비밀 없는 fixture만 사용합니다.
6. workers/document-workflow에서 `uv run python -m dg_workflow.cli --help`, `uv run ruff check .`, `uv run mypy src`, `uv run pytest`를 실행합니다. 각 명령은 해당 코드/설정 생성 후 실행합니다.

완료 조건: 실제 help 출력, fixture 처리 결과, CI 기록, 재현 가능한 lock, Rust 버전/계약 일치. 새 워커를 기본 compose 상시 서비스로 추가하지 않습니다.

## 작업 완료 기록

- 작업 브랜치/커밋: `feat/s22-worker-shell`. 커밋은 하지 않았다. compose 서비스는 추가하지 않았다.
- 실행: `--once`, `--drain`, `--job`은 대기 작업이 없으면 종료 코드 0과 `processed: 0`이다. 필요한 환경값이 없으면 종료 코드 2이고, 출력에는 비밀값을 넣지 않는다. `CMS_INTERNAL_BASE_URL`은 `http://127.0.0.1`만 받는다.
- help: `uv run python -m dg_workflow.cli --help`가 `--once`, `--drain`, `--job`, `--document`, `--rust-contract`를 보여 준다.
- fixture: `fixtures/synthetic-note.json`을 `--once --document`로 넣으면 `{"schemaVersion": 1, "command": "once", "processed": 1, "title": "합성 메모"}`와 종료 코드 0이다. timeout이 나면 그 실행이 만든 임시 파일만 지운다.
- Rust: `dg-content contract`는 `{"schemaVersion":1}`이다. `validate -`는 JSON stdin을 검사한다. `cargo test -j 2 --test cli`는 2 passed. 워커의 `--rust-contract`도 `{"schemaVersion": 1}`을 출력했다.
- WSL: `wsl.exe -l -v`에는 `docker-desktop`만 있다. Linux용 Rust 바이너리로 JSON stdin을 넘기는 smoke는 미실행이다. Windows 경로를 WSL 경로로 바꾸지 않는다.
- 검사: `uv run ruff check .`, `uv run mypy src`는 통과했다. `uv run pytest`는 15 passed. 의존성은 추가하지 않아 기존 `uv.lock`을 유지했다. C: 여유는 18.42 GiB다.
- CI: `.github/workflows/document-workflow.yml`은 `workers/document-workflow/**`가 바뀔 때만 `uv sync --locked`, ruff, mypy, pytest를 실행한다.
- 다음 작업: M8-01. 문서 워크플로 구현 완료로 표시하지 않는다.
