# UI/UX 구성과 디자인 원칙

> v5.0 기준: [[SCOPE_v5]] 적용. 주력 Kotlin·Rust·TypeScript·PostgreSQL. LLM·C++ 제외, Go는 국소 배포 도구로 필요할 때만 사용합니다. 로컬 자원은 [[02_RESOURCE_BUDGET]] 참조.
## 정보 구조

공개 상단 메뉴는 소개 / 프로젝트 / 노트 / 리서치 / 탐색입니다. 로고는 홈으로 연결합니다. 프로젝트 상세에는 설명과 과정 기록을 구분합니다. 관리자에는 글·프로젝트·분류·미디어·발행·검색 상태·설정을 배치합니다. 공개 방문자 회원가입은 없습니다.

## 시각 방향 — 신규 제안

아이보리 배경 #F5F2EA, 짙은 녹색 #173C32, 연한 구획 #E6EBE1, 절제된 황토색 강조를 사용합니다. 기본 본문은16~18px, 줄간격1.6~1.8, 읽기 본문폭720~800px를 시작값으로 두고 구현 시 검증합니다. 대비·반응형·focus는 실제 브라우저에서 검사합니다. 이미지에서의 색상만으로 접근성 통과를 선언하지 않습니다.

## 공개 읽기 UX

제목→요약→본문→근거/관련 글 순서로 읽습니다. 데스크톱 목차는 오른쪽, 모바일 목차는 접이식으로 제안합니다. 코드와 표는 화면 전체를 넘치게 하지 않고 해당 영역에서 가로 스크롤합니다. 목록은 제목·짧은 요약·주제·날짜로 판단할 수 있게 합니다.

## 작성 UX

자동 저장 상태와 공개 상태를 분리합니다. 제목/본문은 중앙, 분류·프로젝트 연결·대표 이미지는 보조 패널입니다. 좁은 화면에서는 글 정보 패널을 접습니다. 미리보기는 실제 공개 렌더러를 사용합니다. 발행 클릭 후 작업 상태로 이동하며 접수202를 성공으로 표시하지 않습니다. 이력 복원은 새 초안입니다.

## 상태 UX

로딩 / 빈 데이터 / 결과 없음 / 권한 없음 / 저장 실패 / 충돌409 / 요청 제한429 / 서비스 장애503을 구분합니다. 모델이 꺼지면 검색은 유지합니다. 철회 화면은 API 차단과 CDN 정리 진행을 구분합니다. 삭제·철회·복원 동작은 영향과 대상 수정본을 확인할 수 있도록 합니다.

## 반응형·상호작용 기준

360px부터 내용이 읽히게 하고 데스크톱 레이아웃은1440px 시안 기준입니다. 키보드로 메뉴·폼·대화상자를 조작하고 focus를 복귀시킵니다. 버튼·폼에는 명확한 라벨과 오류 위치를 제공합니다. hover만으로 기능을 숨기지 않습니다. 터치 영역은44px를 설계 목표로 둡니다.

## 이미지 해석 규칙

wireframes는 정보 배치, ui는 색상 적용 레이아웃, mobile은 좁은 화면 패턴, concepts는 브랜드 분위기 참고입니다. 생성형 컨셉의 작은 문구나 도식은 정확한 시스템 명세가 아닙니다. **계약·기능 명세 → 화면 명세 → 와이어프레임 → 컨셉 이미지** 순으로 구현 기준을 적용합니다.
