# WF05 입력 안전·출처·처리 한도

다음 값은 작은 개인 사이트를 위한 시작 정책이며 실측 후 조정합니다.

| 항목 | 초기 정책 |
|---|---|
| 동시 처리 | 워커 1개, 작업 1개 |
| PDF | 텍스트 PDF, 최대 10MiB·100페이지; 암호화·손상·이미지 전용은 안내 후 중단 |
| Markdown | UTF-8, 최대 2MiB; HTML 실행·외부 include 금지 |
| HTML URL | http/https 중 운영에서는 https 우선, 응답 최대 5MiB, redirect 최대 3회 |
| 추출 텍스트 | 총 1백만 문자 상한, 초과는 잘라 저장하지 말고 사용자에게 분할 요청 |
| 실행 | 단계별 timeout, 추출 subprocess 60초 시작; 검토 대기 시간은 실행 timeout 제외 |
| 재시도 | 네트워크/503 등 일시 오류만 최대 3회, backoff와 nextAttemptAt 기록 |

## URL 수집 출시 게이트

첫 단계에서는 URL을 단순 출처 링크로만 저장해도 됩니다. 자동 fetch는 아래 검증 완료 후 활성화합니다. https URL이라도 안전하다고 가정하지 않습니다.

- 사용자정보 포함 URL·비허용 포트·file/data/ftp를 거절합니다.
- DNS 결과의 모든 IPv4/IPv6가 public 주소인지 확인하고 loopback/private/link-local/metadata 주소를 차단합니다.
- DNS 재바인딩을 막기 위해 실제 연결 IP도 검증·고정 가능한 fetch 구현을 사용합니다. 리다이렉트마다 재검증하며 자동 redirect에 맡기지 않습니다. 이 보장을 구현할 수 없으면 URL fetch는 비활성화합니다.
- 네트워크 레벨 egress도 내부 서비스와 클라우드 metadata로의 접근을 차단합니다. Kotlin 내부 API용 연결과 외부 fetch client를 분리합니다.
- 응답 Content-Length를 신뢰하지 않고 스트리밍 수신량을 제한합니다. 압축 해제 후 크기·시간도 제한합니다.
- 쿠키·관리자 토큰·브라우저 세션을 외부 호스트로 전달하지 않습니다. 로그인/구독 벽을 우회하지 않습니다.

## 파일과 렌더링

확장자·MIME·파일 signature를 교차 검사하고 임의 경로를 받지 않습니다. 추출 subprocess를 시간/메모리 제한 가능한 환경에서 실행합니다. 개발 Windows의 단순 RSS 관측은 강제 메모리 격리와 다름을 기록합니다. HTML과 Markdown은 검토 화면에서도 sanitize하고 PDF는 다운로드 링크로 제공합니다.

## 자료 사용

외부 원문은 비공개 검토 자료입니다. 공개 초안에는 출처와 사용자가 선택한 발췌·직접 작성한 해설만 넣고 전체 원문 자동 복제를 금지합니다. 제목·저자·날짜는 추출값임을 표시하고 검토합니다. 검색 미리보기에도 비공개 원문이 섞이지 않게 합니다.

원문·토큰·쿠키·전체 URL query를 로그로 남기지 않습니다. checkpoint에는 원문 대신 artifact 참조를 넣습니다. 보존·삭제는 [[WF06_OPERATIONS]]를 따릅니다.
