# 격리 복원

기능: 백업을 운영 데이터베이스가 아닌 다른 데이터베이스와 다른 디스크에서 확인한다.
목적: 복원 시험이 `datagrizzly` 원본을 덮지 않게 한다.
연관: `infra/ops/backup.mjs`, `entry_denylist`, 릴리스 `manifest.json`.

백업 대상은 데이터베이스, 첨부, 철회 목록, 릴리스 매니페스트, `workflow` 스키마의 체크포인트다. 같은 서버 디스크에만 복사한 파일은 백업으로 치지 않는다. 스냅샷이 가리키는 첨부가 없으면 복원을 성공으로 닫지 않는다.

2026-11-15에 `datagrizzly`를 덤프해 `datagrizzly_m6restore`로 복원했다. 철회 목록 1건과 릴리스 1건이 같았다. 복원 데이터베이스와 덤프 파일은 확인 후 지웠다. 파일은 C: 안에만 있었으므로 외부 백업으로 보지 않는다. RTO 4시간과 RPO 24시간은 목표로 남아 있다.
